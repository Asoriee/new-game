# 📘 Руководство по скиллам, плагинам и экстремальной экономии токенов

> Полный практический справочник по настройке кастомизаций Antigravity (скиллы, плагины, правила, MCP-серверы) и регламент экономии токенов для максимальной скорости работы и точности ИИ-агента.
> Подходит как готовая инструкция для переноса в любой новый проект.

---

## ЧАСТЬ 1. Архитектура кастомизаций Antigravity

Antigravity поддерживает двухуровневую систему расширений: **Глобальную** (для всех проектов на компьютере) и **Локальную** (для конкретного репозитория).

### 1.1. Структура каталогов
```text
УРОВЕНЬ 1: Глобальный (C:\Users\<Имя>\.gemini\config\)
├── rules/                  # Глобальные правила поведения агента
├── skills/                 # Общесистемные скиллы
└── plugins/                # Изолированные плагины

УРОВЕНЬ 2: Локальный в проекте (корневая папка .agents/)
.agents/
├── rules/
│   └── rules.md            # Специфичные правила текущего проекта
├── skills/
│   ├── task-observer/      # Мета-скилл наблюдения за паттернами
│   ├── ui-ux-pro-max/      # Дизайн-система и мобильный UX
│   └── grill-me/           # Интервью и стресс-тест архитектуры
├── plugins/                # Бандлы кастомизаций для проекта
├── workflows/              # Автоматизированные пайплайны
├── mcp_config.json         # Подключение внешних MCP-серверов
└── hooks.json              # Триггеры событий жизненного цикла
```

### 1.2. Анатомия скилла (`SKILL.md`)
Каждый скилл — это отдельная директория в папке `skills/<skill_name>/`, обязательно содержащая файл `SKILL.md` с YAML frontmatter:

```markdown
---
name: my-custom-skill
description: Краткое, но ёмкое описание возможностей скилла и условий, при которых агент обязан его активировать.
---

# Инструкции для агента
Здесь описываются правила, последовательность действий, примеры и ограничения.
```

* **Триггер активации**: Агент сканирует поле `description` при получении запроса пользователя. Если задача соответствует описанию, агент считывает `SKILL.md` и исполняет инструкции.
* **Вспомогательные файлы**: Внутри папки скилла могут находиться подкаталоги:
  * `scripts/` — скрипты автоматизации (Node.js / PowerShell / Python).
  * `references/` — углубленная документация и справочники.
  * `data/` — JSON-базы, палитры, пресеты.

### 1.3. Анатомия плагинов (`plugins/`)
Плагин — это самодостаточный модуль, объединяющий в себе скиллы, правила и MCP-конфигурации:
```text
plugins/game-dev-pack/
├── skills/
├── rules/
└── plugin.json
```

## ЧАСТЬ 2. Установка и подключение в новый проект

### 2.1. Быстрый перенос в новый проект (Merge 2 / Game Dev)
Чтобы развернуть настроенную среду агента в новой папке проекта:
1. Создайте в корне нового проекта папку `.agents/`.
2. Скопируйте папки `rules/` и `skills/` из текущего проекта:
   ```powershell
   Copy-Item -Recurse -Path "c:\projects\magic-shop-tycoon\.agents" -Destination "c:\projects\new-game\.agents"
   ```
3. Скопируйте базовый файл правил `docs/GAME_SUCCESS_FORMULA.md` в `.agents/rules/rules.md`.
4. Настройте файл `mcp_config.json` в `.agents/` (или глобально), чтобы агент имел доступ к инструментам памяти и сжатия.

### 2.2. Настройка MCP-серверов (Model Context Protocol)

#### 1. Claude-Mem (Долговременная память между сессиями)
* **Назначение**: Позволяет агенту помнить прошлые сессии, ключевые баги и решения без повторного чтения кода.
* **Запуск локального воркера**:
  ```powershell
  npx claude-mem start
  ```
  Воркер работает локально на порту `http://localhost:37777`.
* **Использование агентом**: Вызов `session_start_context` в самом начале диалога.

#### 2. Headroom (Семантическое сжатие контекста)
* **Назначение**: Сжимает длинные дампы логов, ответы терминала и структуры данных без потери технического смысла через инструменты:
  * `headroom_compress` — сжать входящий текст.
  * `headroom_retrieve` — извлечь детали при необходимости.

## ЧАСТЬ 3. Арсенал активных скиллов и как их использовать

### 1. `task-observer` («One Skill to Rule Them All»)
* **Где лежит**: `.agents/skills/task-observer/SKILL.md`
* **Как работает**: Фоновый мета-скилл непрерывного самообучения. Отслеживает ошибки, трения, повторяющиеся паттерны пользователя и автоматически документирует улучшения в `skill-observations/`.
* **Когда вызывать**: Активируется в самом начале сложных мультишаговых задач или при ретроспективах.

### 2. `ui-ux-pro-max` (Профессиональный мобильный интерфейс)
* **Где лежит**: `.agents/skills/ui-ux-pro-max/SKILL.md`
* **Как работает**: База данных из 79 стилей, 192 цветовых палитр, 119 правил UX, микро-анимаций GSAP/CSS и адаптивных мобильных стандартов.
* **Как вызывать**: Любые задачи по верстке интерфейса, созданию карточек, модалок, тач-таргетов $\ge 44 \times 44\text{ px}$ и CSS Compositor анимаций.

### 3. `grill-me` / `grilling` (Архитектурное интервью)
* **Где лежит**: `.agents/skills/grill-me/SKILL.md`
* **Как работает**: Перед тем как писать код в неопределенных или рискованных задачах, агент задает структурированные вопросы пользователю через интерактивный инструмент `ask_question`, предлагая рекомендуемые варианты ответа.
* **Как активировать**: Сказать агенту «проинтервьюируй меня», «протестируй решение» или использовать команду `/grill-me`.

### 4. `agy-customizations` & `antigravity-guide`
* **Где лежат**: Встроенные системные скиллы Antigravity.
* **Как работают**: Справочники по внутренней архитектуре IDE, хукам, горячим клавишам и правилам создания расширений.

## ЧАСТЬ 4. Золотой регламент экономии токенов (Token Economy)

Раздувание контекста приводит к:
1. Замедлению ответа агента (TTFT).
2. Потере фокуса и галлюцинациям в коде.
3. Быстрому исчерпанию лимитов сессии.

Ниже приведены **12 нерушимых правил**, соблюдение которых экономит до 75% токенов за сессию:

### Правило 1. Точечное чтение вместо чтения файлов целиком
* ❌ **Запрещено**: `view_file` без параметров на файлы больше 100 строк.
*  **Правильно**: Сначала найти номер строки через `grep_search` или `Select-String`, затем прочитать срез `StartLine: 40, EndLine: 90` (не более 40–80 строк).

### Правило 2. Запрет `list_dir` на корень репозитория
* ❌ **Запрещено**: Делать `list_dir` корневого каталога (выгружает сотни строк с `node_modules`, `dist` и конфигами).
*  **Правильно**: Использовать описание структуры в Knowledge Item (`project_context.md`) или запрашивать конкретные узкие подпапки (`src/components/`).

### Правило 3. Хирургические правки (Surgical Edits)
* ❌ **Запрещено**: Перезаписывать файл целиком через `write_to_file(Overwrite: true)` для изменения 5–10 строк.
*  **Правильно**: Использовать `replace_file_content` с точным совпадением контекста из 3–6 строк до и после изменения.

### Правило 4. Группировка несмежных правок
* ❌ **Запрещено**: Делать серию последовательных вызовов `replace_file_content` к одному и тому же файлу (каждый шаг отправляет diff в контекст).
*  **Правильно**: Один вызов `multi_replace_file_content` со списком `ReplacementChunks`.

### Правило 5. Фильтрация вывода терминала (Piping & Head)
* ❌ **Запрещено**: Запускать команды, вываливающие мегабайты текста (сырой `git log`, `npm list`, дамп директорий).
*  **Правильно**: Всегда фильтровать вывод через конвейер:
  ```powershell
  # Ограничение первыми/последними строками
  git status -s
  Get-ChildItem -Name | Select-Object -First 20

  # Выборка только ошибок и предупреждений
  npm run check 2>&1 | Select-String "Error|Warning|error|warning"
  npm run build 2>&1 | Select-String "Error|Warning|error|warning"
  ```

### Правило 6. Абсолютный запрет поллинга процессов (No Polling)
* ❌ **Запрещено**: Запускать циклы ожидания и спамить инструментом `manage_task(status)` каждую секунду.
*  **Правильно**: Запустить фоновую команду и завершить свой ход. Система Antigravity сама пришлет событие `[Message] task finished`, когда процесс завершится.

### Правило 7. Сжатие объемных данных через Headroom
* ❌ **Запрещено**: Помещать в контекст неструктурированные дампы JSON на 500 строк или сетевые ответы.
*  **Правильно**: Пропускать тяжелые массивы через инструмент `headroom_compress`.

### Правило 8. Разогрев сессии через Claude-Mem вместо исследования кода
* ❌ **Запрещено**: На старте каждой новой сессии заново «исследовать проект», читая `package.json`, `App.svelte`, `store.ts` и т.д.
*  **Правильно**: Первый вызов — `session_start_context(project: "...")` и чтение актуального артефакта `project_context.md`. Весь контекст подгружается за 1 секунду.

### Правило 9. Запрет повторного чтения (No Re-reading)
* ❌ **Запрещено**: Читать повторно один и тот же блок кода, если агент сам его читал 2 шага назад и внешних изменений не было. Информация уже есть в контекстном окне.

### Правило 10. Запрет пересказа и словесной воды
* ❌ **Запрещено**: Начинать ответ с пересказа задания («Вы попросили меня сделать файл, поэтому я сейчас расскажу, как я делаю файл...»).
*  **Правильно**: Сразу результат, суть решения и ссылки на измененные файлы `[file.ts](file:///...)`.

### Правило 11. Лимит циклов «правка — тест — исправление» (Максимум 3)
* ❌ **Запрещено**: Бесконечно крутиться в цикле автоисправления одной и той же ошибки более 3 раз.
*  **Правильно**: Если за 3 итерации билд не починен — остановиться, честно сформулировать корень проблемы и запросить уточнение у пользователя через `ask_question`.

### Правило 12. KI First (База знаний вместо сканирования файлов)
* ❌ **Запрещено**: Изучать архитектуру проекта поиском по десяткам файлов.
*  **Правильно**: Поддерживать единый документ контекста (`project_context.md`) и читать только его. Синхронизировать его при любых ключевых изменениях архитектуры.
